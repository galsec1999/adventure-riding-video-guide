# מדריך הווידאו לרכיבת אדוונצ'ר

אתר סטטי בעברית וב־RTL שמרכז סרטוני לימוד מאומתים לרכיבת אדוונצ'ר, שטח וכביש. האתר מציג ספריית וידאו, חיפוש דו־לשוני, מסננים, מסלולי למידה ומצב משתמש מקומי — ללא הרשמה וללא Backend.

מערך הנתונים הנוכחי הוא Snapshot מאושר של 130 רשומות ב־`data/videos.json`: ‏60 רשומות Wave 1 שנבדקו מחדש ו־70 רשומות Wave 2 שנוספו לאחר אימות מקור. ה־runtime והמאמת הכללי אינם תלויים במספר זה ומקבלים כל מערך לא־ריק ותקין; שערי סבב מפורשים קובעים את הכמות הצפויה. זהו שלב ביניים: יעד השחרור המלא שב־`MASTER_SPEC.md` הוא לפחות 200 סרטונים מאומתים.

## הפעלה מקומית

### דרישות

- Python 3.9 ומעלה.
- Node.js 20 ומעלה לצורך בדיקות ה־JavaScript (אין חבילות runtime חיצוניות).
- דפדפן מודרני.
- לצורך אימות JSON Schema: חבילת `jsonschema` של Python.

התקנת התלות היחידה הנדרשת לאימות הנתונים:

```powershell
python -m pip install jsonschema
```

כלי המחקר `tools/youtube_research.py` הוא כלי תחזוקה אופציונלי ודורש `yt-dlp`. הוא אוסף מטא־דאטה בלבד ואינו מוריד וידאו או תמלול; אין צורך בתלות זו להפעלת האתר או להרצת שערי הנתונים הרגילים.

אין צורך בתהליך build כדי להפעיל את האתר. עם זאת, אין לפתוח את `index.html` ישירות באמצעות `file://`, מפני שהדפדפן עשוי לחסום טעינת JSON. יש להשתמש בשרת המקומי המצורף.

### Windows

מתיקיית הפרויקט:

```powershell
.\run-local.bat
```

### Linux ו־macOS

```bash
chmod +x run-local.sh
./run-local.sh
```

לאחר ההפעלה פותחים בדפדפן את [http://127.0.0.1:8000/](http://127.0.0.1:8000/). עוצרים את השרת באמצעות `Ctrl+C`.

אפשר להעביר אפשרויות לשרת דרך שני סקריפטי ההפעלה:

```powershell
.\run-local.bat --port 8080 --open
```

```bash
./run-local.sh --port 8080 --open
```

האפשרויות הזמינות הן `--host`, `--port` ו־`--open`. ברירת המחדל הבטוחה היא האזנה ל־`127.0.0.1` בלבד. אין להשתמש ב־`--host 0.0.0.0` אלא ברשת מהימנה.

## מבנה הפרויקט

- `index.html` — נקודת הכניסה לאתר.
- `assets/` — CSS, JavaScript ונכסים חזותיים.
- `data/videos.json` — רשומות הסרטונים המאושרות.
- `data/categories.json` — מילון התחומים, הקטגוריות והערכים המבוקרים.
- `data/learning-paths.json` — מסלולי הלמידה והפניות לסרטונים.
- `data/synonyms.json` — מילים מקבילות בעברית ובאנגלית עבור החיפוש.
- `data/site-config.json` — שם האתר, מחבר, קהילה, לוגו ופרטי קשר.
- `schema/video.schema.json` — JSON Schema לרשומת וידאו.
- `tools/` — שרת מקומי, אימות נתונים, בדיקת קישורים ובניית דוחות.
- `tests/` — בדיקות אוטומטיות.
- `reports/` — דוחות ביקורת, תוצאות בדיקה וצילומי מסך.

## הרצת בדיקות

יש להריץ את הבדיקות מתיקיית השורש של הפרויקט.

### אימות נתונים

```powershell
python tools/validate_data.py
```

פלט JSON ל־stdout:

```powershell
python tools/validate_data.py --json
```

שמירת דוח מפורט:

```powershell
python tools/validate_data.py --report reports/data-validation.json
```

האימות בודק בין היתר Schema, מזהים ייחודיים, התאמת URL ל־YouTube Video ID, הפניות פנימיות, קטגוריות, תגיות ומסלולי למידה.

ברירת המחדל בודקת מאגר לא־ריק ללא מכסה קשיחה. בשער תוכן שבו נדרש מספר מדויק משתמשים ב־`--expected-count`; בשער שחרור משתמשים ב־`--minimum-count`:

```powershell
python tools/validate_data.py --expected-count 60
python tools/validate_data.py --expected-count 130
python tools/validate_data.py --minimum-count 200
```

האפשרויות `--expected-count` ו־`--minimum-count` הדדיות ואי־אפשר להעביר את שתיהן יחד. מדיניות הספירה, הערך הנדרש, הכמות בפועל והתוצאה נרשמים גם בפלט הטקסט וגם בדוח JSON.

`tools/validate_wave1.py` הוא מעטפת Legacy ל־Snapshot של Wave 1 בלבד:

```powershell
python tools/validate_wave1.py --expected-count 60
```

הכלי מפעיל את המאמת המרכזי עם ציפייה מפורשת ל־60. הוא אינו מאמת שחרור ואסור להשתמש בו כשער הכמות אחרי סבב 03.

### בדיקות יחידה ו־Smoke

הרצת כל בדיקות ה־JavaScript המבוססות על `node:test`:

```powershell
npm test
```

הרצת הסוויטות בנפרד:

```powershell
npm run test:unit
npm run test:smoke
```

קיצורי דרך לכלי התחזוקה:

```powershell
npm run validate
npm run audit
```

אם נוספו בדיקות Python תחת `tests/`, מריצים גם:

```powershell
python -m unittest discover -s tests -p "test_*.py"
```

בדיקות הסקלביליות מייצרות בזיכרון fixtures מבודדים של 130 ו־300 רשומות על בסיס המבנה המאומת, בלי לכתוב אותם ל־`data/videos.json` ובלי לארוז אותם. הן בודקות הכנה ואינדוקס, חיפוש, מסננים, מיון, ספירות וטעינה מדורגת, ומדווחות זמני מדידה ללא סף ביצועים שביר.

בדיקות הדפדפן הידניות הנדרשות כוללות Desktop ו־Mobile, חיפוש בעברית ובאנגלית, מסננים משולבים, RTL ומקלדת, היעדר שגיאות JavaScript, יצירת נגן רק לאחר לחיצה ושמירת מועדפים, נצפה והתקדמות לאחר רענון. במובייל התפריט ומגירת המסננים נועלים את הרקע, נסגרים ב־Escape ומחזירים מיקוד; בדסקטופ המסננים נשארים חלק מהעמוד ואינם נועלים גלילה.

## בדיקת קישורים

ברירת המחדל היא dry-run מקומי: היא בודקת את מבנה כתובות YouTube ואת התאמתן למזהים, ללא טענה שהסרטון ציבורי כרגע.

```powershell
python tools/check_links.py
```

בדיקה מקוונת חוקית מול YouTube oEmbed/HTTP ושמירת דוח:

```powershell
python tools/check_links.py --online --report reports/link-check.json
```

אפשר לשלוט בזמן ההמתנה ובמספר הבדיקות המקבילות:

```powershell
python tools/check_links.py --online --timeout 15 --workers 4 --report reports/link-check.json
```

זמינות YouTube משתנה עם הזמן. כשל רשת אינו הוכחה שהסרטון נמחק; יש לבדוק את סיבת הכשל ולתעד אותה לפני שינוי נתונים.

## בניית דוח תוכן

הפקת דוחות JSON, CSV ו־HTML תחת `reports/`:

```powershell
python tools/build_audit.py
```

כאשר דוח הקישורים נשמר בשם של סבב, מעבירים אותו במפורש כדי שה־Audit יקשר לדוח הנכון:

```powershell
python tools/build_audit.py --link-report reports/phase-03-link-check.json
```

יעד חלופי:

```powershell
python tools/build_audit.py --output-dir reports/runtime
```

יש להריץ שוב אימות נתונים, בדיקות קישורים לפי הצורך ובניית דוח לאחר כל שינוי תוכן מאושר.

## הוספת סרטון

אין להוסיף סרטון על בסיס כותרת או thumbnail בלבד.

1. פותחים את מקור YouTube ומוודאים שהסרטון ציבורי ופעיל.
2. בודקים מטא־דאטה ותוכן באמצעות תיאור, Chapters, כתוביות/תמלול או צפייה בחלק רלוונטי.
3. מוסיפים ל־`data/videos.json` רשומה התואמת ל־`schema/video.schema.json`.
4. משתמשים במזהה פנימי מהצורה `yt-VIDEO_ID` ובכתובת מלאה התואמת בדיוק ל־Video ID.
5. בוחרים תחום, קטגוריה, תגיות ושאר הערכים רק מתוך `data/categories.json`.
6. כותבים תקציר עברי מקורי, נקודות למידה, התאמה לרוכב ואזהרות בטיחות לפי הצורך.
7. משאירים `null` או מערך ריק כאשר פרט אינו מאומת; אין להמציא משך, תאריך, כתוביות, פרקים או נקודות זמן.
8. מוסיפים הפניות לסרטונים קשורים או למסלול למידה רק למזהים קיימים.
9. מריצים את אימות הנתונים, בדיקות היחידה ובניית הדוח לפני commit.

אין להוריד או לשמור את קובץ הווידאו עצמו. האתר משתמש בקישור, בהטמעת YouTube וב־thumbnail הרשמי בלבד.

## שינוי קטגוריה או מילון מונחים

הערכים שב־`data/categories.json` משתמשים במזהי `snake_case` יציבים. לשינוי בטוח:

1. מוסיפים או מעדכנים את הרשומה במילון המבוקר.
2. מעדכנים כל הפניה מושפעת ב־`data/videos.json` וב־`data/learning-paths.json`.
3. מעדכנים מילים מקבילות ב־`data/synonyms.json` כאשר הדבר משפר חיפוש עברי–אנגלי.
4. מריצים `python tools/validate_data.py` ומוודאים שאין הפניות או תגיות לא ידועות.

אין לשנות מזהה קיים בלי לבצע ולתעד migration של כל ההפניות אליו. אין לשנות סיווג מאומת כדי להתאים את המידע לעיצוב.

## שינוי שם, לוגו, קהילה ופרטי קשר

עורכים את `data/site-config.json` ב־UTF-8:

- `site_name_he` — שם האתר בעברית.
- `author_name` — שם המחבר.
- `community_name` — שם הקהילה; אפשר להשאיר מחרוזת ריקה אם לא הוגדר.
- `contact` — פרטי קשר אמיתיים בלבד; אפשר להשאיר ריק.
- `logo_path` — נתיב יחסי לקובץ לוגו מקומי תחת `assets/`; אפשר להשאיר ריק. כתובות חיצוניות, `data:`, `javascript:`, נתיב מוחלט או מעבר `..` נדחים, ובטעינה כושלת מוצג סימן ה־fallback המובנה.
- `safety_warning_he` — נוסח אזהרת הבטיחות המאושר מתוך `MASTER_SPEC.md`.
- `default_language` ו־`direction` — ברירות המחדל של השפה וכיוון הממשק.

שם האתר מחובר לכותרת המסמך, למטא־תיאור, למותג ול־ARIA. שדות מחבר, קהילה ופרטי קשר מוסתרים כבלוק שלם כשהם ריקים. לאחר השינוי מריצים את האתר ובודקים Desktop ו־Mobile. אין להכניס לוגו, פרטי קשר או שם קהילה מומצאים. נוסח הבטיחות חייב להישאר תואם ל־`MASTER_SPEC.md`; שינוי מהותי בו דורש החלטה מתועדת ב־`DECISIONS.md`.

## פרסום ב־GitHub Pages או באחסון סטטי

האתר אינו זקוק לשרת יישומים. יש לפרסם את תיקיית הפרויקט כך ש־`index.html`, `assets/`, `data/` ויתר קובצי האתר נשמרים באותם נתיבים יחסיים.

ב־GitHub Pages:

1. דוחפים branch מאומת ל־repository המתאים — אין לבצע force push.
2. בהגדרות repository פותחים **Pages** ובוחרים פרסום מ־branch ומהתיקייה `/ (root)`.
3. ממתינים לסיום ה־deployment ופותחים את כתובת Pages.
4. בודקים טעינת JSON, חיפוש, מסננים, חלון וידאו וקישורים ישירים בסביבת הפרסום.

אותו עיקרון מתאים לכל שירות hosting סטטי. אין לפרסם `.env`, מפתחות API, secrets, cache, דוחות runtime או קבצים זמניים. אין צורך במפתח YouTube בצד הלקוח.

## פתרון תקלות

- **הנתונים אינם נטענים:** ודאו שהאתר נפתח דרך `http://127.0.0.1` ולא באמצעות `file://`.
- **הפורט תפוס:** הפעילו `run-local.bat --port 8080` או `./run-local.sh --port 8080`.
- **`jsonschema` חסר:** הפעילו `python -m pip install jsonschema` ונסו שוב.
- **כשל בקישור מקוון:** בדקו רשת, timeout ותגובת YouTube; אל תמחקו רשומה על סמך timeout יחיד.
- **תוצאה חסרה בחיפוש:** בדקו תחילה את הטקסט והתגיות המאומתים ואת `data/synonyms.json`; אין לשנות עובדות כדי לאלץ תוצאה.

## בטיחות וזכויות

הסרטונים נועדו להעשרה ולמידה ואינם מחליפים הדרכה מעשית של מדריך מוסמך. יש לתרגל בהדרגה, במקום בטוח, עם ציוד מיגון מתאים ובהתאם לחוק, לתנאי הדרך ולרמת הרוכב.

האתר מרכז ומסווג מקורות לימוד חיצוניים. כל הזכויות בסרטונים שייכות ליוצרים ולערוצים המקוריים. יש להציג קרדיט ולקשר למקור; אין להעתיק תמלולים מלאים או תיאורים ארוכים.

`MASTER_SPEC.md` הוא מקור האמת העסקי. `NEXT_ACTION.md` קובע את הסבב הפעיל, ואין להתחיל סבב חדש לפני השלמת הסבב הנוכחי.
